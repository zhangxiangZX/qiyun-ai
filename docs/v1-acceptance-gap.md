## 〇、一句话结论

**V1 主干闭环在"询盘生成"之后就断了**：询盘 `/inquiries` 实测 **500**、报价 `/quotes` 实测 **404**，导致询盘中心/询盘详情/报价管理/成交回写整条链路当前不可用。同时主导航挂着一批 V1 明令"不做"的 V2 功能（CRM 域、套餐账单、系统状态、操作日志、渠道接入、地域、销售分析、业务规则等），**范围违反**。

## 二、8 条上线标准逐条判定（执行包 10·八）

| # | 上线标准 | 判定 | 说明 |
|---|----------|------|------|
| 1 | 一个客户企业可开通企业空间 | ⚠️ | 企业空间/租户机制代码存在，未实机验证开通流程 |
| 2 | 老板/管理员/销售可分别登录 | ⚠️ | 登录链路存在；三角色菜单区分见第三节 |
| 3 | 销售可发链接和快速录入 | ⚠️ | 链接/录入前端在；后端提交链路（环节 4–6）未全通 |
| 4 | 客户可通过手机端提交需求 | 🔍 | AI 选型页手机端未实机验证 |
| 5 | 询盘中心能统一展示客户机会 | ❌ | `/inquiries` 500，询盘中心无法加载 |
| 6 | 销售能按系统提示跟进客户 | ⚠️ | 跟进任务路由在，但依赖询盘数据 |
| 7 | 销售能创建报价并标记结果 | ❌ | `/quotes` 404，无法创建/改状态 |
| 8 | 老板能看到询盘/跟进/报价/成交结果 | ⚠️ | 统计路由在，但底层数据链路断 |

**8 条中 2 条明确 ❌（5、7），4 条 ⚠️，2 条 🔍 → 当前不满足试点上线条件。**

## 三、角色验收差距（执行包 10·四 / 09·四）

| 角色 | 验收要求 | 判定 | 说明 |
|------|----------|------|------|
| 老板 | 看全部询盘/任务/报价/来源成交统计/管成员 | ⚠️ | 菜单与统计路由在，但数据链路断（见一） |
| 管理员 | 管获客入口/知识库/AI助手/分配询盘/成员 | ⚠️ | 功能存在；询盘分配依赖 `/inquiries`（500） |
| 销售 | 只能看自己的询盘/任务/报价；**不能进知识库/AI助手/团队页** | 🔍 | 前端路由守卫未实机验证；菜单区分见下 |

**菜单区分问题（范围违反的 UX 表现）**：执行包 08·六 禁"所有角色共用一个菜单"，01·二 明确定义三端不同菜单。但当前 `navigation.ts` **所有功能（含 V2）对全角色平铺展示**，无按角色收起超范围项 → ❌ 不符合"销售端极简/三端菜单不同"。注：`hiddenNavigationLinksForMatching` 机制已存在但未被用于收起 V2 菜单。

## 五、范围符合性（执行包 08·六 / 10·一 禁止事项）

执行包明令 V1 **不做**：客户运营、复购、售后、渠道 ROI、角色权限矩阵、**套餐与账单**、**系统状态**、**操作日志**、渠道 API 接入、CRM 对接、地域分布、销售分析大屏、业务规则等。

**当前代码违反（navigation.ts 实测存在并挂主导航）**：

| 超范围功能 | 导航位置 | 判定 |
|------------|----------|------|
| CRM 客户域（档案/运营/复购/工单） | 客户与运营组 | ❌ 违反 |
| 套餐与账单 | 系统设置组 | ❌ 违反（10·一 明确不做） |
| 系统状态 | 超管组 | ❌ 违反 |
| 操作日志（invitations 审计） | 系统设置组 | ⚠️ 边界（审计日志，非大模块） |
| 渠道接入与配置（douyin/wechat/expo） | 渠道与站点组 | ❌ 违反（渠道 API 接入不做） |
| 地域分布 | 客户与运营组 | ❌ 违反（V2 以后） |
| 销售助手分析 | 询盘与报价组 | ⚠️ 边界 |
| 业务规则 | 智能助手组 | ❌ 违反（复杂配置） |
| 跟进日历 / 文档中心 / 地图（V2） | 多处 | ⚠️ 用户已拍板"留 V2"，但未与 V1 菜单区分 |

**判定**：❌ **范围蔓延已发生且暴露在主导航**。之前已在 `docs/BACKLOG.md` + `docs/MVP-V1-0-GAP-STATUS.md` 文档层登记为 V2，但**界面未收起**。
