## 2. UI/UE 设计师视角：细节审计

### 2.1 设计令牌冲突（P0，最隐蔽也最伤一致性）
- `packages/ui/src/styles/theme.css` 定义主色 `--primary: 221 100% 54%`（≈ `#1266ff`）。
- `src/styles/v2-prototype.css:1-30` 在 `:root` **重定义** `--primary:#3f5eff; --bg:#f6f8fc; --text:#172b4d; --radius:10px` 等一套硬编码 hex，且被 `layout.tsx` **全局 @import**。
- 结果：同一 `--primary` 在不同文件取值不一致（#1266ff vs #3f5eff），跨页面主色可能漂移、难以预测。
- **整改**：删掉 `v2-prototype.css` 里对设计系统令牌的覆盖，只保留真正需要的局部变量；所有颜色走 `theme.css` 的 HSL 语义令牌。

### 2.2 三套视觉语言并存（P0）
| 体系 | 代表 | 问题 |
|---|---|---|
| A 设计系统 | `@qiyun/ui` 的 `PageHeader/StatCard/Sheet/ConfirmDialog` | 干净、浅色、语义令牌 ✅ |
| B 手写 CSS Module | quotes/customers/sales-funnel/home-overview/channel-access/team/business-rules | 直接用 `*.module.css` + 原生 table，配色/圆角与 A 不一致 |
| C 深蓝 mockup 侧栏 | `console.css` `.console-sidebar` 写死 `#0d1e40→#07142d` 渐变 | 与 A/B 的浅色 HSL 完全割裂，像是"两个产品拼在一起" |

- **整改**：以 A 为准，B 系页面逐步迁移到 `@qiyun/ui` 原语；C 系侧栏配色收敛到品牌蓝阶（brand-500 `#1266ff` + 浅色/深色双主题），消除"深蓝巨幕 + 浅色内容区"的割裂感。

### 2.3 字体与可读性（基本 OK，小修）
- 字体：`next/font` Inter + `PingFang SC` / `Microsoft YaHei` 中文回退，整体合理。
- 问题：`console.css` 又单独写死 `Inter, var(--font-inter), "PingFang SC"...`，与全局令牌重复定义，易漂移。
- 建议：全仓统一引用 `--font-sans` 令牌，删除散落的字体内联声明。
- 层级：标题/正文/辅助文字的字号阶梯需在 `theme.css` 里固化为 `--text-xs…--text-2xl` 并全量复用，避免各页面自定义 px。

### 2.4 动效与微交互（收一遍，别"花"）
当前动效全为手写 CSS `@keyframes`（`motion.css` / `tailwind.preset.ts`）：`fade-in-up / scale-in / slide-in-down / glow-pulse / ui-canvas-drift / ui-tech-scan`。
- ⚠️ **过度动效**：侧栏激活项 `glow-pulse` **常亮呼吸光**、主画布 `canvas-drift` 持续漂移、卡片 hover 上浮 + 扫光（`ui-tech-scan`）。在密集数据页（报表/客户）会显得"不商务、抢注意力"。
- **整改建议**：
  - 侧栏激活态用静态高亮 + 1 次入场动画即可，去掉常亮呼吸。
  - 主画布背景改为静态低饱和渐变，去掉持续漂移。
  - 卡片 hover 仅保留轻微阴影/边框变化，去掉扫光。
  - 全局已尊重 `prefers-reduced-motion`，保持并扩展到所有动效。
- 该做的微交互（目前缺）：按钮 loading 态、列表项进入的 stagger、抽屉/Sheet 滑入缓动、Toast 出现/消失——这些都已有基础，建议**统一时长（150/300ms）与缓动曲线**形成体系。
