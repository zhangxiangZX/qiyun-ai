## 0. TL;DR（给老板的一句话）

AI云 **V1.0 合规闭环（A–H 模块）完全符合"工业官网获客系统"定位，跑得通**；但代码已按另一份**更宽定位**（《对话式获客 PRD》）实装了一批 **CRM / 报价 / 计费 / 多渠道** 功能，且**直接挂在主导航菜单上、没有隐藏**。问题不在"做了"，在"露了"——V1.0 对外演示时客户会误以为这是交付范围，造成**定位认知混乱**。两把"定位尺子"互相矛盾，PM 必须先拍板"AI云到底是谁"。

---

## 1. 有两把"定位尺子"，而且互相矛盾 ⚠️

同一天（2026-07-07）产出了两份方向不同的定位文档，至今未对齐。

### 尺子 A —— 护栏 V1.0 / 核心项目书 / MVP 清单（"窄定位"）
- **定义**：帮助工业设备制造企业把官网升级为 **AI 接待、产品咨询、询盘留资、线索跟进** 工具的「工业官网获客系统」。
- **明确 P2 不做**：CRM 全功能、复杂订阅计费、全渠道深度客服、工作流编排、Agent/模型市场。
- **允许的信息架构（护栏 §6）**：登录/邀请、Dashboard、知识库、机器人配置、会话中心、线索管理、数据分析、网站诊断、设置中心、套餐展示、官网 Widget。
- **一句话对外表达**：让工业官网同时具备"AI 接待、产品咨询、询盘留资、线索跟进"能力。

### 尺子 B —— 《对话式获客 PRD》v1.0（"宽定位"）
- **定义**：AI 把网站流量自动变成可跟进销售线索，并**闭环到报价 / 客户 / 跟进**。抓 Drift 关停窗口，用"客服+获客+销售跟进"闭环做差异化。
- **把"询盘 → 报价 → 客户 → 成交"做成第一卖点**。
- **明确要上**：按效果计费后台、渠道 ROI、全渠道接入（抖音/微信/小红书）、客户/跟进模块、工单模块、销售助手 AI。

> **矛盾点**：尺子 A 把 CRM / 计费 / 全渠道列为「不做」，尺子 B 把它们列为「第一卖点」。两份文档未对齐，而代码按尺子 B 落了地，又被 PM 决策（2026-07-08）强行标注"归 V2、不计入 V1.0 验收"——**决策只在文档上，没在界面上**。

## 4. 核心判断

### 4.1 V1.0 合规部分：高质量符合窄定位 ✅
A–H 模块全部 DONE，闭环（上传资料→官网提问→AI 回答+来源→高意向留资→销售跟进）真实可跑。这部分**完全对得起"工业官网获客系统"的定位**，是产品的真刀。

### 4.2 超边界部分：符合尺子 B，违反尺子 A
CRM 客户域、报价、成交漏斗、多渠道接入、计费、销售助手、工单、复购——这些**不是垃圾功能**，它们正是《对话式获客 PRD》规划的主卖点。问题不是"做了错事"，是"在 V1.0 这把尺子下，它们属于 P2 / 不做项"。

### 4.3 最大风险是"暴露"，不是"存在"
- 这些 V2 功能**直接挂在主导航菜单**（询盘与报价、客户与运营、成交漏斗、套餐与账单、渠道接入、销售助手），没有用代码里已有的 `hiddenNavigationLinks` 机制收起。
- V1.0 发布演示时，客户/投资人会看到一堆"官网获客"以外的东西，误以为这是交付范围 → **定位认知混乱**，恰好踩中护栏 §0 最警惕的"变成通用平台 / CRM"。
- 护栏 §6 信息架构被突破：新增了"询盘与报价 / 客户与运营 / 成交漏斗 / 套餐与账单"分组，而这些分组在护栏允许列表里**不存在**。

### 4.4 命名也在跑偏
菜单用了"客户档案 / 工单 / 套餐与账单"等词，而护栏明确禁止把产品描述成"CRM / 平台"。对外话术与护栏自相矛盾。

## 5. PM 处置建议（价值判断，非技术细节）

**① 定位对齐决策会（最高优先级，本周内）**
PM 二选一，必须拍板：
- **守窄定位**：AI云 = 工业官网获客系统。V2 那批功能拆成独立 V2 包，不在 V1.0 出现。
- **升宽定位**：正式把《对话式获客 PRD》定为 V2 路线图，更新护栏文档，把 CRM/计费/全渠道从"P2 不做"改为"V2 规划"。
> 无论哪种，当前"文档说不做、菜单在做"的撕裂状态必须结束。

**② V1.0 发布前（低成本、立即做）**
利用代码已存在的 `hiddenNavigationLinksForMatching` 机制，把超边界菜单项（询盘与报价组、客户与运营组、成交漏斗、渠道接入配置、AI 选型独立页、渠道转化数据、套餐与账单、销售助手）从主导航收起；演示中如需展示，单独标注「V2 预览」，不得作为 V1.0 交付承诺（与 2026-07-08 PM 决策一致，但要把决策落到界面）。

**③ 更新护栏文档**
补一节「V2 与 PRD 关系」，消除护栏（窄）与《对话式获客 PRD》（宽）的冲突；明确 V2 边界与触发条件。

**④ 对外话术统一**
菜单与文案去掉"CRM / 平台 / 工单 / 计费"等易引发误读的词，回到"AI 接待 / 产品咨询 / 询盘留资 / 线索跟进"。

---

## 6. 一句话结论

守住"工业官网获客"这把刀，V1.0 已经合格；那批 CRM / 计费 / 多渠道功能**不是不能做，是现在不该混在 V1.0 脸上**。先把它们从导航收起来，再决定它们是 V2 还是新定位——不要把"未来想做"和"现在交付"摆在同一张菜单上。
